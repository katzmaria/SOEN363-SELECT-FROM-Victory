# Source D (Coral Coast Health Service): generation log

> **Statement:** all of this data is entirely fictional, created exclusively for educational and learning purposes (SOEN 363 Project Phase 2). It does not describe real patients and does not include any real personal information. Names are random combinations of common first names and surnames; suburbs and streets are invented; phone numbers come from the Australian ranges reserved for fiction ((02) 5550 xxxx, (02) 7010 xxxx); image links use the reserved `.example` domain.

Generated by `source_d_generator.py` (seed `2061`). Re-running the script reproduces the files exactly. AI tool: Claude Code (Anthropic), model Claude Opus 5.5. Extract time (local): 2025-10-31T18:00:00+11:00 Australia/Sydney (UTC+10, UTC+11 during daylight saving). Admissions span 2022-01-01 to the extract time.

**One record = one entity instance**, wherever it is nested (a patient object, an admission inside it, a diagnosis inside that admission, and so on). Container objects (`meta`, the page wrapper, `vitals`, `address`, `location`, `appointments`) are not records. A record can have several problems, so the problem columns overlap (as section 7 of the contract allows). Every count comes from the script's own bookkeeping, so it is exact.

### Daylight-saving edge cases (all in ClinicalNote `writtenAt`)

Overnight nursing notes on the nights the clocks change. Bare local strings in the skipped hour are counted as **invalid dates** (the time does not exist); bare local strings in the repeated hour are counted as **ambiguous dates** (two possible instants). The ones written with an offset are valid and only count as non-standard format.

- local time in the hour repeated when daylight saving ends (happens twice): 4
- local time in the hour skipped when daylight saving starts (does not exist): 4
- repeated-hour time written with its offset (second, +10:00): 4
- skipped-hour wall time written with its +10:00 offset (valid instant): 4

## How duplicates were made

- **Exact duplicate:** the same record repeated with the **same ID** in the same array, sometimes with one field's case or surrounding spaces changed (still identical after trimming and ignoring case). Exact-duplicate patients are re-sent as stubs without `admissions`, and exact-duplicate admissions without their nested arrays, so no child is duplicated by accident.
- **Near duplicate:** the same facts under a **new ID** (IDs continue after the last original ID), rendered again so dates, labels and phone numbers can use another format. They match the contract's duplicate keys: patient = name + DOB, practitioner = name + role, admission = patient + admit time, others = admission + timestamp + type. For `triage` and `separation`, which are normally single objects, a duplicate turns the key into an array of two objects.

## Source D conventions (for checking your profiling)

- **Timestamps** are local Australia/Sydney time. Usual format: ISO 8601 with the correct offset, `2025-03-14T09:30:00+11:00` (+11:00 in daylight saving, +10:00 otherwise). Also present: UTC with `Z`, milliseconds, no seconds; day-first local strings with no offset (`14/03/2025 09:30` or `14/3/2025 9:30 am`; a slash date in this source is **always** day-first); Unix timestamps (seconds as a number, milliseconds as a number, or seconds as a string; all are true UTC instants); and a few dot dates (`dd.mm.yyyy HH:MM` or `mm.dd.yyyy HH:MM`, both orders occur). A dot date with a part over 12 can be read; a dot date where both parts are 12 or less is one of the injected **ambiguous dates**.
- **Date of birth** (`dob`): usually `YYYY-MM-DD`; also `DD/MM/YYYY`, `5 Mar 1980` / `05-Mar-1980`, Unix **milliseconds of local midnight** (converting that to a UTC date gives the previous day), and ISO midnight with offset (`1980-03-14T00:00:00+10:00`).
- **Temperature** (`vitals.temp`): a plain number in Celsius (sometimes a string), `{value, unit}` with unit `C`/`Cel`/`°C`, or Fahrenheit: `{value, unit}` with `F`/`degF`/`°F`, a bare number in the 90s-100s, or a string like `"99.1F"`. Other vitals are numbers, sometimes strings, sometimes with units (`"96%"`, `"4/10"`, `"120/80 mmHg"`, `{systolic, diastolic}`).
- **Missing-value placeholders** (injected): missing key, `null`, `""`, `"N/A"`, `"-"`, `"?"`; `-1` for numbers; `"0000-00-00"` for dates. Values that are legitimately empty (no `separatedAt` for a current admission, no `orderRef` for a walk-in exam, no report for an exam not done, no `endAt` for a current stay, no phone for young children) are written as `null` or the key is left out, and are **not** counted as problems.
- **Allergies / medications** with none: `none`, `None`, `NKA`, `NKDA`, `nil known`, `Nil known`, `Nil` (sometimes inside a one-element array). These mean "none", not missing. Real values are an array of strings, or sometimes one `; `-separated string.
- **Patient life status** is the boolean `deceased` (sometimes `Y`/`N`, `yes`/`no`, `"true"`/`"false"`, `1`/`0`). A missing `deceased` means unknown, so the schema default (`alive`) applies.
- **ICD-9 codes**: dictionary codes only, sometimes without the decimal point (`4019`), with extra spaces (` 428.0`), or as a JSON number (`401.9`, `486`, `38.9` for `038.9`); plus fake codes from this list: `999.9`, `V99.99`, `123.45`, `E000.0`, `4l0.9`, `880.88`, `555.55`, `XXX.X`, `042.99`.
- **Invalid numbers** are only in optional triage vitals and pain scores (e.g. temperature `300`, heart rate `-72`, SpO2 `140`, pain `14`, `"abc"`). `-1` on its own is the missing-value placeholder, not an invalid number.
- **Malformed** records are either real records with a field of the wrong JSON type (e.g. `writtenAt: true`, `body` as an object, `orderedBy` as an array) or junk entries inside an array (`null`, a bare string, `[]`, `{}`, an error object). Every file is still valid JSON (UTF-8, 2-space indent).
- **IDs** are integers, occasionally written as strings (`"57"`). Children are linked to their admission by nesting; each diagnosis also carries an explicit `patientId`, and each imaging record an optional `orderRef`.
