# Phase 2 - Task 1: Loading and Initial Profile of the Raw Sources

_Generated by `profiling/profile_sources.py`. It describes the data **as delivered**: nothing is cleaned or changed here (cleaning is Task 2)._

## 1. How each format is loaded

`profiling/load_sources.py` loads every source into the same structure: a `SourceData` object holding, for each of the 12 entities, a **list of dicts** (one dict per record) with the source's own field names and the values exactly as read, plus the field order (`layout`), a log of malformed records and a list of structural containers. `to_dataframes()` turns a source into pandas DataFrames if pandas is installed.

| Source | Format | How it is read | Nested records |
|---|---|---|---|
| A - Europe | TXT, 12 files | Split each line on `\|` (see 1.1) | none (flat files) |
| B - North America | CSV, 12 files | `csv.reader` (comma, `"` quotes, header row) | none (flat files) |
| C - Asia | 1 XML file | `xml.etree.ElementTree`, walk `staff`, `icd9Dictionary`, `patients`, `admissions` | children of `<admission>` become their own entity with `admissionNo` added; `<radiologyExam>` inside `<order>` gets `orderRef` = the order's id; `<name><family/><given/></name>` -> `name.family`, `name.given` |
| D - Africa | 1 JSON file | `json.load`, walk `practitioners`, `icd9_reference`, `patients`, `encounters` | encounter arrays (`triage`, `ward_movements`, `diagnoses`, `investigations`, `imaging`, `theatre`, `notes`) and `discharge` (object, list or null) become entities with `encounter_id` added; `contact{...}` -> `contact.address` etc. |

### 1.1 Source A (TXT): delimiter and record layout

* Encoding UTF-8; one record per line; line end `\n` (`\r\n` tolerated).
* **Line 1 is a header** with the field names.
* Field delimiter **`|`** (pipe). No quoting or escaping: the producer replaced any `|` inside a value with `/`, so every `|` is a delimiter.
* A valid data line has exactly as many fields as the header; any other line is **logged** in `malformed_records.csv` (not loaded, not dropped silently).
* Missing values are written as an empty field or `N/A`. Decimals use a comma (`37,2`).

## 3. Field names, inferred types and missing values

*Inferred type* = the most common value format among non-missing values. *Conforming* = share of non-missing values that fit that type. *Missing* counts every way the source writes 'no value' (absent key/element, JSON null, empty text, or a marker such as `N/A`, `NULL`, `unknown`). *Other formats* lists values that do not fit the inferred type: these are the formatting differences and invalid values inside one field.
