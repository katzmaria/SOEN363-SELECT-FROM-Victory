# Profile of the raw sources (Task 1)

Generated by `task1_load_profile/profile_sources.py` from the raw files, **before** any cleaning. The full tables are in `output/profile/` (`record_counts.csv`, `field_profile.csv`, `duplicates.csv`, `format_differences.csv`, `invalid_values.csv`, `malformed_records.csv`).

## 1. Sources and how they are loaded

### Source A - CHU de Montclair-sur-Loire (Europe, Europe/Paris)

- **Format:** TXT, one file per entity in `data/raw/A_txt/`, UTF-8, LF line endings.
- **Delimiter:** pipe `|`. No quoting or escaping (a `|` inside a value was replaced by `/` at export).
- **Record layout:** line 1 is a header with the field names; every following line is one record with exactly one value per header field (so `len(header) - 1` pipes). Empty field = no value.
- **Loading:** each line is split on `|` (no CSV quoting rules apply). A line whose field count differs from the header (truncated line, or a stray `|` inside a value) cannot be aligned to the columns and is **logged as malformed** with its file, line number and text, then left out of the table.
- **Data structure:** one table per file (`common/tabular.py`: column names + one dict per record); every value kept as raw text.

|---|---|---|
| `professionnels.txt` | professionals | `id_pro|titre|nom_prenom|fonction|service` |

### Source B - Uganda National Hospital (Africa, Africa/Kampala)

- **Format:** CSV, one file per entity in `data/raw/B_csv/`, UTF-8.
- **Delimiter:** comma `,`. Minimal quoting: a value containing a comma, a double quote or a line break is wrapped in `"..."`, and a quote inside it is doubled (`""`). Some clinical notes span several physical lines.
- **Record layout:** line 1 is a header with the field names; each record has one value per header field. Empty field = no value.
- **Loading:** read with Python's `csv` module (not line by line), so quoted commas and line breaks stay inside their value. A record whose field count differs from the header is **logged as malformed** with its file, line number(s) and text.
- **Data structure:** one table per file; every value kept as raw text.

### Source C - Straits Regional Medical Centre (Asia, Asia/Singapore)

- **Format:** one XML file `data/raw/C_xml/hospital_records.xml`, UTF-8, parsed with `xml.etree.ElementTree`.
- **Root:** `<hospitalRecords>` with attributes `system=Straits Regional Medical Centre`, `continent=Asia`, `timezone=Asia/Singapore`, `extractTime=2025-10-31T18:00:00+08:00`.
- **Nesting:** `<staff>/<member>`, `<patients>/<patient>` (name split into `<name><family/><given/>`), `<admissions>/<admission patientRef=..>` which **contains** its `<triage>`, `<wardMovement>`, `<diagnosis patientRef=..>`, `<labOrder>` (its `<imaging>` exams nested **inside** the order), walk-in `<imaging>`, `<operation>`, `<note type=..>` and `<discharge>`. `<unlinkedRecords>` holds children that carry `admissionRef=..` instead of being nested.
- **Extraction:** every nested record becomes one row of its entity's table; the parent keys are taken from the structure (`@admission` = enclosing `<admission>`, `@orderRef` = enclosing `<labOrder>`), or from `admissionRef` / `orderRef` attributes. Attributes become `@name` columns, child elements become columns, `<temperature unit=..>` gives `temperature@unit`. An absent element is None, an empty element is `""` (both are counted as missing).
- A record **without its id attribute** cannot be identified: it is **logged as malformed** (with its element path and XML) and left out.

### Source D - Coral Coast Health Service (Oceania, Australia/Sydney)

- **Format:** JSON, `data/raw/D_json/practitioners.json` (`practitioners[]`) and three pages `patients_p1..p3.json` (`patients[]`, plus `unlinkedEncounters[]` in page 3), parsed with `json`. Each file has a `meta` object (export time 2025-10-31T18:00:00+11:00).
- **Nesting:** `patients[]` -> `admissions[]` -> `triage` (an object, or an array of two when duplicated), `diagnoses[]`, `clinicalNotes[]`, `orders[]`, `imaging[]` (with an optional `orderRef`), `procedures[]`, `wardStays[]`, `separation` (object/array = discharge record). `unlinkedEncounters[]` are admissions that carry their own `patientId`.
- **Extraction:** every nested object becomes one row of its entity's table. The parent is taken from the structure (the enclosing patient / admission). Sub-objects are flattened: `vitals.bp/hr/rr/temp/spo2` (a `{value, unit}` temperature gives `vitals.temp@unit`, a `{systolic, diastolic}` blood pressure gives `s/d`), `address` and `nextOfKin` objects become one text value, lists of allergies or medications are joined with `; `, `appointments[0].at` is the follow-up time. JSON numbers are kept as their exact text (so `250.00` stays `250.00`).
- **Malformed:** junk array elements (`null`, a bare string, `[]`, `{}`, an error object) and records with a field of the wrong JSON type (e.g. `writtenAt: true`, `body` as an object, `orderedBy` as an array, `modality` as a number) are **logged as malformed** with their JSON path and left out.

## 4. Fields: inferred types and missing values

Note: an empty optional value can be legitimate (no discharge time for an active admission, no order for a walk-in exam).
